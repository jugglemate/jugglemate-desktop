> 对应包：`jugglemate-agent`（内部 `jugglemate-web`）
> 面向：需要修改 / 扩展坐席工作台的同学（开发、测试、二次开发）。
> 产品视角与功能清单见 `docs/PRODUCT.md` / `docs/功能清单.md`。

---

## 1. 技术栈与环境

- **框架**：Vue 3 + Vite + Vue Router + Electron
- **IM SDK**：`jugglechat-electron`（坐席端 IM 能力封装，本地另含 `src/libs/juggleim-es-1.9.13.js`）
- **Node**：`>=20.19.0 || >=22.12.0`（见 `package.json` engines）
- **包管理**：项目用 `pnpm`（含 `pnpm-workspace.yaml`）；也可用 `npm`

### 1.1 常用命令

```bash
npm install                 # 安装依赖
npm run dev                # Vite 开发服务器（前端热更新）
npm run build              # 产出 dist/（前端打包）
npm run electron:dev       # 以 Electron 启动桌面端（需先 build 或 dev 起服务）
npm run electron:build     # 打包桌面安装包（dmg/zip/...）

# 国内加速（electron 二进制镜像）
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run electron:build
```

> `electron:build` 走 `electron-builder`，配置见 `package.json` 的 `build` 段（appId `com.jugglemate.agent`、mac 签名/entitlements、icon 等）。

## 3. 设计系统与命名规范

### 3.1 CSS 引入顺序

`main.js` 依次引入：`hubchat.css`（token 基底）→ `hubchat-custom.css`（组件样式）→ `login.css`（登录页）。

### 3.2 设计 Token（节选自 `hubchat.css`）

- 颜色：`--bg-root` / `--bg-surface` / `--bg-elevated` / `--bg-hover`、`--text-primary / secondary / tertiary`、`--accent / --accent-dim`、`--border-subtle`
- 形状：`--radius-md`、`--shadow-md`
- 字体：`--font-sans`
- 动效：`--transition-fast`

**新增样式一律引用 token，禁止硬编码颜色/尺寸。**

### 3.3 命名前缀（重要）

- `tyn-` 是**历史**样式名（来自早期 snailchat 迁移），新代码**不要再用**。
- 新代码统一用 `jm-` 前缀，如 `.jm-sender`、`.jm-messages`、`.jm-msg`、`.jm-reply-quote`。
- 不要混用两套前缀。

## 4. 关键扩展点

### 4.1 新增消息类型

1. 在 `src/components/message/` 新建 `MessageXxx.vue`。
2. 在 `MessageItem.vue`（路由分发器）按 `message.name` 增加分支。
   - 设计原则：父组件只 `v-for` + `<MessageItem :message="m" />`，新类型**只动分发器一处**。
3. 气泡与内容分离：`MessageBubble` 管方向/状态/重发，`MessageXxx` 只管内容渲染。
4. 右键菜单可拔插：`MessageContext` 发 `context/open`，由 `ChatMain` 统一弹 `MessageMenu`，不耦合具体业务。

### 4.2 接入 IM 事件

- 网关 `src/common/im.js` 已封装并 re-export 全部 SDK 枚举。
- 已订阅：`STATE_CHANGED / CONVERSATION_CHANGED / CONVERSATION_ADDED / CONVERSATION_REMOVED / MESSAGE_RECEIVED / MESSAGE_RECALLED / MESSAGE_UPDATED / MESSAGE_READ / MESSAGE_REACTION_CHANGED / MESSAGE_REMOVED / CONVERSATION_TOP`。
- 自定义消息：`jgd:grpntf`(群通知) / `jgd:friendntf`(好友通知) / `jgd:contactcard`(名片) / `snl:sticker`(动画表情) / `snl:typing`(typing，非存储) / `snl:replay`(群接龙)。
- 新业务消息（如 `jgm:ticket_assign` / `jgm:csat`）在 `im.js` 订阅后在对应组件渲染。

### 4.3 调用后端接口

- 业务接口统一走 `src/services/api.js` + `src/common/request.js`。
- `request.js` 自动带 `AppKey` / `Authorization`（取自 localStorage），遇 401 清 token 跳登录。
- 新增接口：在 `api.js` 加方法 → `request.js` 发 → 组件/服务消费。

## 5. 配置与硬编码（必读）

> ⚠️ 以下为当前已知技术债，二开/部署时务必注意（详见 `docs/PRODUCT.md` §10）：

- **`src/config.js` 硬编码**：API 基址 `localhost:8050`、IM server `wss://ws.snailchat.im`、AppKey `nwm6fxqt2aeebhb7` —— 换环境必须改这里，未走环境变量。
- **会话与消息全在内存**：不使用 IndexedDB/SQLite，刷新即丢（冷启动不恢复）。
- **`src/services/agent.js` 中 SSE 请求仍硬编码 AppKey / Authorization**：海外化、安全改造的高优先级项。
- 会话搜索框仅为样式，未接后端。

## 6. 依赖原则（来自 `docs/im-migration-plan.md`）

- **不引入新 npm 包**：图片预览用原生 `<dialog>`，复制用 `navigator.clipboard`。
- 从同源 `snailchat-web` 迁移 IM 能力时，剥离 `wr-*` iconfont 与 OKLCH 硬编码，改用 `jm-` token + 简洁 SVG / Unicode。

## 7. 调试技巧

- 开发用 `npm run dev` 起 Vite，再用 `npm run electron:dev` 起壳（或浏览器开 dev server）。
- 登录走 `src/services/user.js`，成功写 `hubchat_user_auth_token` 并触发 `im.connect`。
- IM 连接状态变化会发 `connection.state.change`；未连接时会话列表显示本地占位。
- 可通过 `localStorage` 的 `hubchat_*` key 观察/清理登录态。
